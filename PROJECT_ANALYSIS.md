# UniTax Pro - Complete Project Analysis

Last reviewed: 2026-11-26

This document is a technical and operational analysis of the UniTax Pro web application, its freemium/licensing model, Firebase data layer, and the Google Apps Script email gateway.

---

## 1. Executive Summary

UniTax Pro is a static GitHub Pages ERP/accounting web application backed by Firebase Realtime Database and a Google Apps Script mail gateway.

The product is currently in a hybrid state:

- The ERP UI is a mature static multi-page app with hash routing.
- Authentication is client-side with SHA-256 password hashing and server-side OTP delivery.
- Freemium accounts are `standard_user` with a single-user workspace.
- Paid multi-user licenses upgrade the owner to `administrator` with `masterControl: "administration"`.
- Email delivery is free: Google Apps Script `MailApp` / `GmailApp`, Google Sheets templates, Firebase Spark, and public IP lookup providers.
- OTP generation and verification are server-side in Apps Script.
- All non-OTP system emails are generated by application events, written to Firebase `System/EmailQueue`, and drained by a 1-minute Apps Script trigger.
- Promotional email is the only admin-composable email category, along with `custom_message`.

The most important current fact: **the live GitHub Pages deployment and the live Apps Script deployment are stale**. Local code is complete, but the public site still uses the old authentication and OTP path. Until the files in this repository are published and the Apps Script version is updated, new system email behavior will not appear.

## 4. Authentication and Roles

### Role model

Freemium and guest accounts must never be administrators.

| Account type | Role | Notes |
|---|---|---|
| New signup / guest | `standard_user` | Single-user workspace |
| Legacy alias | `free_owner` | Backward-compatible alias only |
| Paid multi-user owner | `administrator` | Granted only by license purchase |
| Paid admin control flag | `masterControl: "administration"` | Required for User Admin panel |
| Revoked/downgraded owner | `standard_user` | `masterControl: "operations"` |
| Platform root | `super_administrator` | Static master console only |

### Admin panel rule

The User Admin panel requires **both**:

1. A paid multi-user license, and
2. An administrator/co-admin role.

Role alone is not enough. This prevents a free account from gaining team provisioning by editing only its role field.

### OTP flow

OTP is generated and verified server-side in Apps Script.

Browser actions use:

```js
UnitaxMail.otp.send(email, purpose, context)
UnitaxMail.otp.verify(email, otp, purpose)
```

Supported purposes:

- `login`
- `signup`
- `forgot_password`
- `resend`
- `master_2fa`

OTP details:

- 10-minute expiry
- Maximum 3 attempts
- Cooldown per email and purpose
- Firebase audit records in `System/OtpRequests`, `System/OtpCooldown`, `System/OtpLogs`
- Public IP and approximate location are collected from free public IP services
- Browser geolocation permission is never requested
- Failed IP lookup never blocks OTP

The OTP context text is hidden on the login screen. IP and location are still shown as badges inside security emails.

## 5. Freemium and Licensing

### Free workspace

A free account has:

```js
role: "standard_user"
masterControl: "operations"
multiUserLicensed: false
workspacePlan: "single_user"
multiUserQuota: 1
```

Free accounts still appear in:

- Paid & Multi-User Licensed Workspaces
- Companies & Workspaces Directory

This is intentional for platform governance. Visibility does not grant admin control.

### Paid workspace

Granting a multi-user license sets:

```js
role: "administrator"
masterControl: "administration"
multiUserLicensed: true
workspacePlan: "multi_user"
multiUserQuota: 25
licenseAutoRevoked: false
licenseValidUntil: <epoch ms>
```

Supported periods in the admin license modal:

- 1 month
- 3 months
- 6 months
- 1 year
- Custom days

### Renewal

Choosing a license period for an already licensed workspace is treated as a renewal.

Renewal does:

- clears `licenseAutoRevoked`
- replaces `licenseValidUntil`
- sends `license_renewed`
- restarts 7-day, 3-day, today, and expiry notices

### Revoke

Manual revoke sets:

```js
role: "standard_user"
masterControl: "operations"
multiUserLicensed: false
workspacePlan: "single_user"
multiUserQuota: 1
```

and sends `workspace_license_revoked`.

### Automatic expiry revoke

The Apps Script trigger `checkLicenseExpiry()` runs daily at 06:00 IST.

For expired licenses it:

1. Sends `license_expired`
2. Calls `revokeExpiredLicense()`
3. Downgrades the owner to `standard_user`
4. Sets `masterControl: "operations"`
5. Sets quota to 1
6. Sets `licenseAutoRevoked: true`

Auto-revoke happens once. A new grant/renewal is required to restore access.

## 6. Email System Architecture

### Canonical endpoint

```text
https://script.google.com/macros/s/AKfycbx7NIHQPjtDxOxCh8hj2CrxV1EtuTM6DxJ-jowWDjWpcKd3-4GM6RFuJIObjDI12H92/exec
```

```text

```

Health check:

```text

```

### Core rule

Browser code never contains `MAIL_GATEWAY_TOKEN`.

Only these actions are called directly from the browser:

- `otp_send`
- `otp_verify`
- `preview`

All other email sends are written to Firebase and processed server-side.

### Queue flow

```text
Browser event
  -> UnitaxMail helper
  -> Firebase System/EmailQueue
  -> Apps Script processEmailQueue() every 1 minute
  -> render Google Sheet template
  -> MailApp or GmailApp
  -> Firebase System/EmailLogs and System/EmailStats
```

### Firebase email paths

| Path | Purpose |
|---|---|
| `System/EmailQueue` | Pending and completed send jobs |
| `System/EmailCampaigns` | Campaign records and status |
| `System/EmailLogs` | Per-recipient send/failure audit |
| `System/EmailStats` | Daily send count for quota guard |
| `System/EmailDedupe` | Idempotency keys |
| `System/OtpRequests` | Active OTP state |
| `System/OtpCooldown` | Resend throttling |
| `System/OtpLogs` | OTP send/verify audit |

### Transport

| Category | Transport | Sender name |
|---|---|---|
| Transactional / security / account | `MailApp` | `UniTax Pro` |
| Promotional | `GmailApp` with `List-Unsubscribe` | `UniTax Pro Notifications` |
| Promotional fallback | `MailApp` | `UniTax Pro Notifications` |

In-body Unsubscribe is always present in promotional templates. One-click `List-Unsubscribe-Post` is opt-in via `UNSUB_ONE_CLICK = TRUE`.

Daily guard: 90 sends/day, leaving headroom under the Gmail free allowance.

## 15. Security Review

### Current risks

| Risk | Severity | Detail |
|---|---|---|
| Firebase rules are fully open | High | Anyone can read/write any node |
| Client-side SHA-256 password hashing | High | Should use Firebase Auth or server-side auth |
| Hardcoded fallback gateway token in Apps Script | Medium | Rotate and keep only in Script Properties |
| Public app key is not a secret | Low | Accepted for OTP/preview only |
| Browser can write directly to Firebase queue | Medium | Expected for current architecture, but rules should later restrict paths |
| Static master credentials in `login.html` | High | Move to environment/server-side auth |

### Recommended hardening

1. Enable Firebase Authentication.
2. Replace client-side password hashing with server-side verification.
3. Lock RTDB rules by path and authenticated UID.
4. Move the Apps Script token exclusively to Script Properties.
5. Rotate `MAIL_GATEWAY_TOKEN`.
6. Validate queue writes with App Check or a server-side proxy.
7. Move static master credentials into a secure backend.
8. Add rate limits to OTP and queue endpoints.

## 16. Known Design Decisions

- `free_owner` is retained only as a backward-compatible alias for `standard_user`.
- Every account appears in admin directories, but admin power requires a paid license.
- OTP is deliberately server-side because browser-side OTP is unsafe.
- Promotional mail uses `GmailApp` for native unsubscribe headers.
- System mail uses `MailApp` to remain within the free quota.
- No in-body logo is used; sender avatar is handled at the Google Account level.
- Expired licenses are auto-revoked once, then must be renewed manually.
